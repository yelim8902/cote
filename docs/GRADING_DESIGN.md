# 코드 채점 시스템 설계

현재 구현된 **간이 채점**은 참고 코드와 사용자가 입력한 코드의 **유사도(단어 겹침 비율)**만 계산합니다.  
실제로 “정답 여부”를 판단하려면 아래 방식 중 하나를 선택해 확장할 수 있습니다.

---

## 1. 테스트 케이스 + 코드 실행 (가장 확실한 방식)

- **방식**: 각 주제(예: 단일 연결 리스트, 버블 정렬)마다 **입력/출력 테스트 케이스**를 정의하고, 사용자 코드를 **실제로 실행**해 출력이 기대값과 같은지 비교합니다.
- **구현 예**:
  - **Python**: 브라우저에서 [Pyodide](https://pyodide.org/)로 사용자 코드 실행 → stdout/반환값 캡처 후 기대값과 비교.
  - **Java/C**: 브라우저만으로는 실행이 어려우므로 **백엔드 서버**에서 Docker 등 샌드박스로 코드 실행 후 결과 반환 (예: Judge0 API, Piston API 등).
- **장점**: 정확한 정답/오답 판별 가능.  
- **단점**: 페이지·언어별로 테스트 케이스와 실행 환경을 준비해야 함.

---

## 2. LLM 기반 채점 에이전트

- **방식**: 사용자 코드 + 문제 설명(또는 참고 정답 코드)을 **LLM API**(OpenAI, Claude, 등)에 보내서,  
  “정답인지 / 어떤 점이 다른지”를 자연어로 판단하게 합니다.
- **구현 예**:
  - 프론트에서 입력 코드와 문제 식별자만 전달.
  - 백엔드(또는 서버리스 함수)에서 프롬프트 구성 후 LLM 호출.
  - 응답을 그대로 또는 요약해서 “정답입니다” / “다음 부분을 수정해 보세요: …” 형태로 표시.
- **장점**: 테스트 케이스를 세밀히 만들지 않아도 되고, “왜 틀렸는지” 설명까지 받을 수 있음.  
- **단점**: API 비용·키 관리 필요, 완전한 정확성은 보장하기 어렵고, 네트워크 필요.

---

## 3. 하이브리드 (현재 유사도 + 선택적 실행/LLM)

- **1단계**: 지금처럼 **유사도 채점**으로 “참고 코드와 얼마나 비슷한지”만 빠르게 보여줌.
- **2단계**: “정확한 채점” 버튼을 두고,  
  - Python은 Pyodide로 실행 + 테스트 케이스 비교,  
  - 또는 “LLM으로 채점”을 선택하면 2번 방식 호출.
- 이렇게 하면 기본은 가벼운 유사도, 필요할 때만 실행/LLM을 쓰도록 할 수 있습니다.

---

## 정리

| 방식              | 정확도 | 구현 난이도 | 비고                    |
|-------------------|--------|-------------|-------------------------|
| 유사도만 (현재)   | 낮음   | 쉬움        | 참고 코드와의 유사도만  |
| 테스트+실행       | 높음   | 중간~어려움 | Pyodide(파이썬) 또는 백엔드 |
| LLM 채점 에이전트 | 중간   | 중간        | API 키·비용 필요        |

**추천**:  
- 우선은 **Python 페이지만** Pyodide + 1~2개 테스트 케이스로 “실행 채점”을 붙이고,  
- 나중에 “설명이 필요할 때”만 LLM 채점 옵션을 추가하는 방식이 무난합니다.  
- 채점 에이전트는 “LLM을 호출해서 채점 결과를 만들어 주는 서비스”라고 보면 되고, 반드시 별도 에이전트 프레임워크가 있어야 하는 것은 아닙니다.
